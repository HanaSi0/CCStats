# CCStats Desktop 内部迭代

本轮仅移植、修改和内部验证，不创建新的发行标签或发布 EXE。

## 桌面工作台

独立 Windows 应用，自动识别游戏进程，提供战绩查询、筛选、收藏/标签、CSV/JSON 导出、结算详情、地图/职业/玩家分析、个人纪录、个人资料、段位趋势、四区官方榜单、时间线、技能分析、按需高级推算和 2D/3D 回放。

历史数据库以只读连接读取。自有资料库单独保存在 `%LOCALAPPDATA%\CCStatsDesktop`；相同记录去重，重新读取保留用户自己的收藏与标签。回放与分析按需加载，位置数据使用现有压缩格式保存，结算未知值显示为 —。

3D 使用后台构建的冻结模型、单色调色板纹理、限定动态顶点预算；地图、棋子、朝向、防御球、极限技、召唤物和场地机制复用现有规则。范围裁剪、动态状态、旧记录缺失数据等边界继续保留，不伪造位置或判定。性能须以实际 Windows 游戏环境验证，不能把离线检查当成实机帧率。

## 自动识别与后台运行

启动后每 2 秒查找游戏，优先前台客户端。匹配地址后连接，进入水晶冲突时可自动记录。异常会延迟重试，切图会收尾上一段。设置可关闭自动识别或自动记录。

点击关闭时，选择“立即退出”或“最小化到托盘”，可勾选“记住我的选择”；在设置中随时恢复询问或更改。托盘状态保留采集与写盘；托盘图标可恢复窗口或退出。真正退出先停止采样、完成当前记录，再释放数据库。

## 数据边界

独立只读采集已接入已加载玩家的位置、朝向、体力、职业、服务器名称与状态，以及经过类型/范围检查的队伍、推进、水晶对象、LB 召唤物、场地施法、场景资源状态和保留的动作效果槽。个人资料另外读取客户端累计场次、胜场与段位，不由本机观测次数代替。公开布局仍需真实客户端验证；已有记录可展示的字段不等于当前采集器能够完整获取这些字段。不能用血量差替代伤害来源，不能把观测片段算作有效胜率样本。

动态冲刺带边界和书库供给/桥梁状态等既有未映射内容仍是已知差异。需要客户端观测后继续适配。

## 完整适配进度（2026-10-19）

本轮补齐了持久状态与动作效果槽的独立读取、去重、召唤物归属、回放保存、数据库/JSON 往返、推进数字、个人资料缓存和观察来源说明。所有读取只请求进程查询与读取权限；没有向游戏进程写入或加载代码。

效果槽最多保留 32 条，轮询不能保证不漏事件，也没有可靠的命中时间与当时完整状态。记录明确标为观测片段，不加入胜率；防御减伤和免控推算不使用事后状态假装精确快照。官方结算仍未完成字段映射，不能称为完全适配。

采集页新增“导出采集诊断”。读到可见的 PvP 结算界面时，保存有类型、索引的有限基本字段到 observations/diagnostics；只采集结算界面，不转储任意内存。最多保留 64 份结算采样，另保留 12 段观测汇总，导出 ZIP 总计上限 32 MiB。它用于核对当前版本的结算字段，尚不把未知索引解释成伤害或胜负。诊断写盘失败不会终止位置记录。

需要在当前国际服实际完成一局并保留结算界面几秒，再导出诊断；以此确认签名、队伍偏移、结算索引及效果槽的覆盖情况。没有该实机证据，不能承诺完整结算和瞬时事件已可靠采集。静态名称来源见 research/desktop-client-identities.json；场景资源状态仅保存原值，尚未验证的桥梁/冲刺带边界不作推断。

本轮本机检查：100 项独立读取/资料库/背景采样检查、686 项原有回归检查通过；桌面 Release 构建零警告、零错误。原有版本 Release 构建通过，保留 88 项既有警告。新增读取仅经结构化夹具检查，实机适配状态按上方限制处理。

未确认推进的帧使用负值缺失标记，回放隐藏进度显示，曲线不将其当作 0%。已确认名单时仅记录十名参赛者；名单未知且超过十人时明确记录限额说明，防止观战角色导致现有移动编码失败。无网络实体编号的场景物体以场景编号和槽位组成记录内标识，不假称为网络实体编号。

控制状态还保存实际来源实体，解析为已加载角色或召唤物主人；缓存时长从剩余时间扣除，过期状态不计入观测控制秒数。可识别吸血与自身回返治疗分开显示。

补核客户端符号后，结算采样包含实际名为 ColosseumRecord 的窗口；同时保留有界的文字节点、坐标和文本原始编码，便于将数字与本地化列标题对应。遍历最多 2048 节点、512 条文本，且只读取已打开的结果窗口。

## 实机采样入口

Windows 内部验证工作流 `Validate desktop changes (no release)` 的手动运行参数 include_test_package 默认关闭。维护者主动打开该选项时，才保留已通过检查的内部测试 ZIP（7 天），不创建 Release，不更新库链；普通代码推送仍只保留验证报告和截图。验证工作流尚未合入默认分支时，也可由维护者在 review/claude-walkable 的提交说明加入 [internal-test-package]，为该次通过检查的构建保留内部测试 ZIP。它只保存在 Actions 构建附件，不创建正式发行或更新下载库。

实机步骤：启动软件并登录国际服角色，完成一局水晶冲突，停留结算窗口至少 6 秒；在“自动采集 → 导出采集诊断”保存 ZIP。诊断中的客户端版本、ColosseumRecord 基本字段和文字节点用于验证结算对应关系。完整瞬时事件的覆盖与命中状态仍须另行验证，诊断通过不代表效果槽轮询已经无遗漏。

诊断还包含实际客户端版本与各通道状态（例如名单校验失败、推进不可读、结果窗口未打开），用于区分版本适配问题与尚未进入对局/结算的正常状态。

效果按目标、效果槽和类型去重，空施放阶段不会占用后续命中阶段的去重键；回放分别保存施放与已观察命中阶段。

本机角色名直接来自已确认的本地角色槽，不依赖个人资料界面是否已加载。榜单页在游戏连接或切换角色后刷新本人的高亮，不额外抓取榜单。

重新识别会先收尾旧记录，再选择当前游戏；已完成片段通过队列交给后台导入，即使连续切图/重连也不依赖单个“最后保存路径”。

诊断导出前会轮换当前观测片段，连接与采集继续；ZIP 同时附最近 12 段的按技能伤害/治疗/自身回返治疗及承伤汇总，便于与结果表对照，不传出完整回放。汇总不代表结算，差异也可能涉及持续伤害、过量治疗或未观察到的事件。

名单与推进状态独立校验：推进字段失配不会丢弃已验证的队伍；诊断在范围校验失败时保留这七个声明字段的数值，以定位偏移/单位差异，不转储其他内存。

## 界面精简

移除默认角色输入和独立采集页面，当前导航为 11 页。启动后始终自动识别游戏、进入水晶冲突后后台记录；旧配置中的关闭选项和手填默认角色不再影响运行。诊断导出移至“设置 → 支持与诊断”。侧栏显示程序集版本号，“关于”提供正式产品、数据与许可说明。

## 采集与交互修正

- 本地身份仅由 Control.GetLocalPlayer 对应的只读静态指针确认，不再假定对象表第 0 槽位是本人。不登录不绑定，切换角色重新确认，断开连接清除活动身份。
- 服务器/状态页读取失败不会丢弃位置和体力；名单需关联对象名、职业及服务器后才赋予队伍。名单失配不再清空角色。场景状态读取独立于名单和推进字段。
- 每张水晶冲突地图保留最近一份有界 Probe 诊断，包含读到的对象数量、拒绝原因、机制名称编号和原始场景状态；即使没有玩家帧，回城后仍可导出。未验证的编号不直接渲染成已知机制。
- 短于 3 秒的区域 0 加载画面不会切段。比赛记录与采集片段分栏，片段不伪装为额外比赛；容量轮换和诊断导出仍会保留必要分段。尚未确认比赛开始/结束的服务器字段，不宣称已实现完整对局边界。
- 自绘日期范围、快捷日期、整行表格选中与可靠行激活；回放支持点击跳转和大范围拖动，拖动期间暂停，松手恢复之前的播放状态。
- 七套配色覆盖按钮、下拉列表、表格、输入区和时间轴；重置恢复基础文字色，自定义选中背景自动选择黑/白正文。
- 机关保镖与阴阳师按原始实体去重，移动后的旧施法位置不再产生第二个人物。阴阳师使用立体闭眼/睁眼模型。榻榻米仅由实测读条/命中事件驱动预备和翻转，红色范围随事件显示，结束后恢复；缺失历史事件不补造。

本轮读取链路测试使用内存读委托注入，调用与 Windows 相同的 ExternalGameReader.Sample；不是只测试脱离地址读取的解码函数。当前环境没有真实国际服进程，客户端版本适配及瞬时事件完整性仍需新诊断包确认。

本轮本地验证：111 项独立读取/导入/后台记录检查、696 项原有功能与共享机制回归检查通过；原有版本 Release 构建通过（88 项既有警告）。Windows 检查另覆盖日期快捷范围与弹出日历、整行选择、主题重置、时间轴跳转及松手恢复播放。

## 用户界面精简（第二轮）

导航合并为 9 页：职业/玩家分析合为数据分析，个人纪录/登录身份合为个人中心。个人中心仅展示当前登录角色及其纪录，不再展示旧版客户端累计资料。名称使用真实登录角色，不用关联别名替代；未登录显示未登录角色。读取/导出/筛选/日期统一放入默认收起的“高级”，自定义颜色也默认收起。移除固定副标题、空闲状态与侧栏平台文案；操作结果提示仍保留。滚动条改为随主题变化的圆角滑块，无箭头，支持轨道翻页和拖拽。前台术语使用比赛记录/回放记录与导出诊断；序列化类型和后台自动记录行为保持兼容。

主题预设扩展为 24 种。Windows 标题栏使用系统 DWM 接口与窗口背景/文字同步，包括主题切换和辅助窗口；系统改色接口不可用时使用同色自绘标题栏，保留窗口拖动、缩放与按钮行为。

启动时先显示居中 Logo 与正在打开提示，等待首屏准备后淡出；提供页面、标签、按钮与折叠区动效，并遵循系统动画设置。后台自动识别与记录逻辑保持不变。
