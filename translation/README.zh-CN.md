# 水晶冲突翻译交接包

已通过聊天确认并保存 **374 项译文**，已接入插件显示层，并完成主窗口与战绩列表第一轮调整。其余未确认的界面说明文案仍保留原文。
用户可以继续直接在聊天中回复译文，无需下载文件。CSV 使用 UTF-8 BOM；已确认内容保存在对应 `zh_CN` 列。

CSV 的 `source` 是导出时的 `文件:行号`，源码后续变化时可能移动；回填优先使用 `key`、`sheet` 和 `row_id`。
不同位置相同英文可能有不同含义，保留独立键以便回填。地图/职业的枚举名与完整名称有重复，请保持译名一致。
`03` 是宽松候选清单，`06` 是完整字面量审计，不代表每条都应翻译。两者包含部分相同内容，可只翻译需要显示的部分。

## 保留这些内容

- 不修改 `key`、`sheet`、`row_id`、`original`、`source`、`raw_csharp` 等列；只填写 `zh_CN`，必要时在 `notes` 追加备注。
- 保留 `{表达式}`、格式说明、换行和 `##/###` 之后的 ImGui 控件标识。插值字符串中的 C# 表达式由后续代码回填处理。
- 不直接改 enum 的英文标识、数字值、数据库字段、技能 ID、地图 ID、文件路径、Hook 特征码和正则。
- `PlayerJobHelper.AbbreviationNameMap` 的英文职业名和部分段位字符串参与识别；后续将单独处理显示翻译，保留识别映射。
- 角色名、服务器名和数据中心名不是普通 UI 文案。服务器名可能参与角色身份匹配，不能直接覆盖数据库中的原值。
- 一个技能组合可能包含多个技能或状态，不应把“组合名”和单个技能名混为一项。

## 动态名称与范围限制

插件在运行时按比赛实际遇到的 ID 读取 `Action`、`Status`、`BNpcName` 等表。**源码没有保存游戏内所有名称，也没有当前用户的比赛数据库。**

`02` 导出的是能够从源码确定的 260 个固定行，不能枚举未来比赛中可能出现的所有技能、状态或 NPC。`04` 和源码快照保留了动态读取位置，后续回填会处理“翻译映射优先，缺失项回退”的机制，而不是只做英文字符串替换。

英文原文参考来自 [xivapi/ffxiv-datamining](https://github.com/xivapi/ffxiv-datamining)，固定提交为 `76d22160d687b0e0318071a098ab9eb9d531605f`，对应 `csv/en/Action.csv`、`Status.csv`、`Addon.csv`。
这是公开英文游戏数据参考，**并非国服对应版本的验证结果**。请按实际目标客户端核对译名和 ID；不能因英文表存在该行就认定国服也已支持。

`Status.4086`～`Status.4089` 在该参考快照没有名称，属于源码中的排除项，可留空。Addon 原文可能带游戏控制标记，保留原文、只写译文。

## 已接入的显示层

`PvpStats/Localization/ChineseText.cs` 处理显示翻译和回退，`ChineseText.g.cs` 由 `tools/generate_localization.py` 从已确认的 CSV 生成。
技能、状态采用不同的 ID 字典；同名组合和单个技能分别保存，不自动删掉“连击”等字样。地图、职业、段位等枚举只有显示名改变。
识别用的英文职业名、段位解析键、玩家名、服务器名、数据库字段及枚举数值不进行文本替换。

`ui-layout.zh-CN.json` 是本轮 UI 修改新增的常规界面用语，与用户逐条确认的游戏词汇分开维护，冲突时生成工具会停止报错。
日常更新请运行 `python3 tools/generate_localization.py`。`tools/export_translation.py` 是初始模板导出器，现已拒绝覆盖任何包含译文的目录；不要重新导出空白模板覆盖这些文件。
`source_reference/` 保留翻译交接当时的源码快照，不代表当前修改后的源文件。
